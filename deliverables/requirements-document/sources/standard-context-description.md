### Investigación de Estándares (ISO/IEC/IEEE 29148:2018)

De acuerdo con el estándar internacional **ISO/IEC/IEEE 29148** (Ingeniería de Sistemas y Software - Procesos del ciclo de vida - Ingeniería de Requisitos), la especificación del contexto de un problema no debe ser una simple narración, sino una estructura formal que delimite el entorno operativo y justifique la necesidad del sistema. Para describir un problema de manera apropiada bajo este estándar, se deben definir los siguientes elementos clave:

1. **Contexto del Negocio u Operativo (Entorno):** Describe el ecosistema donde operará el sistema, los actores involucrados y las condiciones externas (sociales, físicas o normativas).
2. **Situación Actual (Estado *As-Is*) y Deficiencias:** Especifica cómo se realizan las operaciones actualmente y cuáles son las limitaciones, cuellos de botella o dolores puntuales que justifican el proyecto.
3. **Concepto de Operación (Estado *To-Be*):** Define de manera general cómo el nuevo sistema cambiará la situación actual y qué capacidades nuevas introducirá en el entorno.
4. **Fronteras y Restricciones del Contexto:** Delimita hasta dónde llega la responsabilidad del sistema y bajo qué restricciones críticas (económicas, temporales, técnicas, regulatorias) debe operar obligatoriamente.
